# 一条命令如何走完整个系统

```text
客户端 ── TCP / RESP2 ──> Reactor（主线程）
                          │ accept / recv / parse
                          │ 按连接切分命令批次
                          ▼
                       有界任务队列
                          ▼
                       工作线程池
                          │ Store 全局互斥锁
                          │ 校验 → AOF append/fsync → KV 修改
                          ▼
                       完成队列 + eventfd
                          ▼
                       Reactor（主线程）
                          │ send / 部分写 / EPOLLOUT
                          ▼
                         客户端
```

## 为什么分离网络与命令执行

socket、epoll 和连接对象只由 Reactor 操作。工作线程拿到命令的副本，执行后把回复放入完成队列，通过 eventfd 唤醒 Reactor，因此不需要让多个线程竞争一个 socket。

一个连接同时只提交一个批次，每批最多 128 条命令。前一批完成后才提交下一批，保证 `SET → INCR → GET` 的执行和回复顺序。不同连接可由不同线程处理；目前 KV 与日志由一个互斥锁保护，所有命令在 Store 层串行，提供命令级原子性。这种线程池并不能让哈希表访问线性扩展，主要隔离网络与命令/磁盘工作，便于下一步研究分片。

完成通知使用递增连接 ID，不使用可能被复用的文件描述符。连接断开后，旧命令的结果不会错误地发给复用该 fd 的新连接。已提交的修改可能在客户端断线后执行，客户端无法仅凭断线判断修改是否成功。

## TCP 与 epoll

TCP 是字节流，一次 recv 可能收到半条命令或多条命令。输入缓冲保留不完整记录；RESP 解析器返回完成、不完整或非法三种状态。长度前缀允许 value 包含零字节和换行。

采用水平触发的 epoll。读写均使用非阻塞 socket，并处理 EINTR、EAGAIN、部分读和部分写。每轮最多接入 128 个连接、每连接读取 256 KiB，避免单连接持续占用事件循环。只有有待发送数据时才监听 EPOLLOUT，避免空转。

收到对端写半关闭后仍执行完整请求并发送回复，再关闭连接。协议错误先返回此前合法命令的回复，再发错误并关闭。QUIT 后续流水线请求不执行。

## 资源边界

最多 4096 个连接；任务队列最多 4096 个等待任务；请求最多 1024 个参数，单参数最多 8 MiB，单连接未消费输入最多 16 MiB，待发送回复最多约 32 MiB。待发送数据超过 1 MiB 时暂停为该连接提交新命令，输出被消费后继续。超限连接可能直接关闭，批次回复超过上限时不保证整批请求执行完毕。

这些边界是教学版防护，不能代替全局内存预算。KV 大小没有上限，完整 MGET 回复会先构造再检查；解析分片时也会重复读取已收到的参数，后续可以改成有状态解析器。慢客户端超时与严格的全局背压属于下一阶段。

## AOF 的顺序与恢复

Store 锁同时保护 KV 和 AOF 顺序。修改成功回复前，默认先完成日志写入与 fsync，再更新 KV。INCR/DECR 被记录为最终 SET；带 TTL 的 SET 被记录为 SET PXAT，过期操作被记录为 PEXPIREAT。恢复先按日志顺序重建，再删除已过期的 key，避免用今天的时间打乱历史状态。

收到成功回复的修改在正常磁盘语义下已持久化；如果客户端未收到回复，修改可能已写入日志。日志写入或 fsync 出错后拒绝后续修改，因为文件里可能有部分记录，不能继续追加并声称成功。磁盘硬件故障、日志被外部修改和恢复过程的内存不足不在本项目的容错范围内。

启动扫描日志时逐段读入，保留一条不完整记录。末尾不完整记录被截断，格式明确错误则拒绝启动。独占文件锁在进程退出或崩溃时由操作系统释放。

## 过期与关闭

GET 等访问按需删除过期 key；每秒提交一次全表清理任务到工作线程池，Reactor 不主动等待 Store 锁。全表扫描是 O(N)，后续适合替换为时间轮或最小堆。

SIGINT/SIGTERM 只设置停止标记；主循环退出后等待已提交任务执行完成，再销毁线程池、连接和 eventfd。关机期间没有保证所有回复送达客户端，已提交命令仍可能被持久化。网络操作失败只回收相应连接。
